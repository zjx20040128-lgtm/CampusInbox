# 电脑端评测与验收

在 `D:\Doc\course-inbox` 使用当前完整项目目录。`start-desktop.cmd` 启动软件，关闭窗口继续驻留托盘；托盘“退出软件”停止。项目仍依赖本机Python、浏览器与相关资源，桌面EXE不是独立安装包。

## 运行评测

### 网页操作（推荐）

启动电脑端后，打开 `http://127.0.0.1:8765/#evaluation`，或点击左侧“连接与工具 → 识别评测”。

1. 查看结果：主页面显示任务识别效果和每条通知平均用时。需要排查问题时，展开“查看问题与逐条结果”。旧版10条标签只评价有无任务，不证明任务身份或延期识别正确。
2. 核对通知：点击“核对通知”，页面会优先切换到可编辑的收件箱通知。对照原文添加任务并填写截止日期；没有任务可直接保存。课程、班级及延期/取消放在任务的补充选项中。点击“保存核对结果”后才参与评分。
3. 开始评测：选择要使用的通知，点击“开始评测”。未核对条目不评分，运行时显示进度并可停止。
4. 更多选项：可从收件箱选取新通知（最多200条）、选择过去的结果、导出当前报告，或选择本机已安装模型开始AI对比（最多三个）。报告不包含原文；本机标注工作文件含原文，勿公开分享。

保存期间继续编辑会保留新修改；其他窗口已改动时需重新加载核对。切换页面或关闭网页不取消后台评测，重启服务会终止未完成评测。本机模型调用需等当前调用结束后才能停止。

网页完成的报告保存在 `data/evaluation/`；兼容读取 `artifacts/evaluation/` 中已有报告。评测使用同轮只读数据库与标签快照，不修改真实消息、任务或模型配置。标注后旧报告不自动重算，应重新运行。样本不足、未覆盖延期、模型回退或调用受限均不能当作PPT目标达成。

### 命令行操作

双击 `start-evaluation.cmd`：使用现有人工标签运行规则评测，窗口显示报告位置，运行结束按任意键关闭。不会向正式收件箱写入测试消息。

在项目目录PowerShell中准备最多200条本机真实消息供人工标注：

```powershell
.\scripts\run-evaluation.ps1 -Action prepare -Limit 200
```

工作文件保存在 `data/verification/notice-labels-workbench-时间.json`，含本机原文，只在本机使用，不纳入开源包。程序不猜测答案，全部初始为 `reviewed=false`。核对后填写 `expected_tasks`，并将该条 `reviewed` 改为 `true`。普通通知应填空数组，任务应按原文逐项填写，例如：

```json
"expected_tasks": [
  {"title": "实验三", "course": "数据库", "scope": "一班", "deadline": "2026-10-26", "operation": "update"}
],
"reviewed": true
```

`operation` 使用 `create/update/cancel`。日期未知填 `null`，只有日期就填 `YYYY-MM-DD`，明确时刻才填带时区ISO时间。任务名/课程与实际字段对应，书名不作课程。明确延期、重复补充、冲突、阅读准备、普通通知都应纳入数据集。不要看模型输出反填答案。

使用核对后的工作文件：

```powershell
.\scripts\run-evaluation.ps1 -Action rules -Labels 'data\verification\notice-labels-workbench-实际时间.json'
.\scripts\run-evaluation.ps1 -Action compare -Models 'qwen3:4b-instruct','qwen3:8b' -Labels 'data\verification\notice-labels-workbench-实际时间.json'
```

比较只调用已安装的本机Ollama模型，不下载、不更改`.env`，拒绝云端及局域网模型地址。Ollama需先运行。尚未安装的8B显示`not_installed`；4B失败后保留规则候选并统计`model_fallbacks`，不能作为模型成功。

报告提供逐项任务匹配的查准率/召回率、截止准确率、更新召回率、操作正确率、缺失/错误/回退、P50/P95延迟。缺失正例计漏检，未人工核对条目不参与评分；旧标签只评任务存在性，不足以证明任务身份正确。报告仅输出哈希和指标。运行后的模型内存/显存是Ollama快照，延迟不包括采集和Windows投递，均不是整机峰值或16GB验收。

## 真实电脑验收与演示

使用可控制的独立发布账号和学生账号，先确认学生页面可见，再检查电脑端，不用真实考试/答题页作自动化测试。

1. 发布一个明确命名、带截止的测试作业，记录发布时间、学生可见时间、电脑采集时间与原文完整性。确认前只应有草稿。
2. 确认任务，再发布延期消息，核对先生成修改方案、确认后改原任务，任务总数不增加，材料保留。
3. 重复通知并补充材料，检查来源合并；再提供不同截止且未声明变更的来源，检查进入冲突核对。
4. 实际观察Windows提示与点击定位。关闭主窗口后再试，记录桌面提醒开关和Windows勿扰状态。
5. 分别实测断网恢复、休眠唤醒和完整退出后重新启动。保留真实漏收和延迟，不用API队列回执代替肉眼观察。
6. 在“学习通同步”导出检查报告，附上人工核对记录。报告中的`real_acceptance=pending`不会因自动回归通过而变为已验收。

现有独立发布测试步骤见 `docs/verification/teacher-published-learning-test-plan-2026-10-15.md`。图片、附件及当前未适配任务入口需要逐项对照原文；列表无漏项不等于附件正文全部读取。

## 学生试用记录

邀请学生由使用者自行进行。每次记录：实际录入/核对耗时、手动录入次数、应发现任务数、漏项数、误报数、错误截止数、是否愿意继续使用、最难理解的页面，以及脱敏后的问题说明。先保留逐次观察，再汇总结果，不用自动回归数据代替学生反馈。

对外演示可按“新消息 → 待确认 → 确认任务 → 延期核对 → 冲突 → 日历/提醒 → 原文与历史”录屏。演示账号和数据应单独准备；本项目不自动发布内容、录制私人消息或公开代码仓库。
