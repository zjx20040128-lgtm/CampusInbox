# 安卓手机后台网页通知

首次用手机打开 HTTPS 提醒页面、输入电脑生成的配对码，再点“开启后台提醒”并允许通知。之后浏览器 Service Worker 可在页面关闭时显示通知；无需本项目的 Android App。电脑必须持续运行并能访问浏览器推送服务，手机必须联网且浏览器允许通知、后台运行。不能保证被系统强制停止或严格省电限制的浏览器仍能送达。

## HTTPS 入口

临时测试：项目启动后，在电脑运行根目录 `启动手机后台提醒.cmd`。脚本只为手机提醒端口 8766 创建 HTTPS 隧道，不开放电脑管理端口 8765。仅在隧道连接及 HTTPS 健康检查都通过后，地址才显示在“手机连接”。临时隧道重启会更换地址，需要用新地址打开手机页面并配对；长期使用应配置稳定的 HTTPS 域名。

已具备域名和反向代理时：让 HTTPS 代理在同一电脑上转发至 `http://127.0.0.1:8766`，保留原始 Host；将 `data/phone-public-origin.json` 配置为 `{"origin":"https://你的域名"}`。服务仅接受该明确域名由本机代理转发的请求；跨域调用、任意域名和电脑管理 API 均不开放。该文件动态读取，无需重新扫码学习通。

当前实测：已定位到脚本强制 HTTP/2 与现有网络不兼容；改用 QUIC 后隧道注册成功。启动脚本现按自动协议选择，并使用项目 Python 的代理/TLS 环境检查入口，避免 PowerShell 误判。外网健康检查及 Service Worker 文件返回 200，电脑管理 API 返回 404，未配对推送公钥接口返回 401。电脑 Edge 可打开安全提醒页面。**安卓手机首次配对、通知授权和锁屏送达仍需真机验收。**

## 使用

1. 浏览器推荐选择明确支持 Web Push 的安卓版本。手机打开“手机连接”中的 HTTPS 地址（局域网 HTTP 地址不具备后台通知权限）。
2. 在电脑生成配对码，手机输入后连接。
3. 点击“开启后台提醒”，允许浏览器网站通知。显示“后台提醒已开启”才代表订阅已保存。
4. 关闭页面后，用真实的新通知验证手机是否弹出系统通知。电脑、手机需联网，但后台推送不要求两者始终在同一 Wi-Fi。
5. 停止接收、关闭后台提醒、断开配对或电脑撤销设备会取消对应订阅。重新打开网页仍可补收未回执的记录。

推送服务返回成功只说明接受了消息，不代表手机已显示；与手机网页读取回执分别记录。推送标题/正文最多 120/400 字，原文完整内容仍在电脑；浏览器推送协议加密。VAPID 私钥经 Windows 当前用户 DPAPI 加密保存。

可选依赖见 `requirements-web-push.txt`。主程序仍可在未安装该依赖时使用原局域网提醒。
