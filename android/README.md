## 首次使用：无需电脑

0.3.11 新增任务截止提醒。在“我的 → 任务截止提醒”开启并允许发送通知；已确认任务按精确截止提前一天、两小时和到期提醒，日期型任务按北京时间前一天/当天上午 9 点及次日上午提醒。任务详情可“修改截止”，保存后重新安排提醒；已提交/已取消不提醒。“已做完”仍需提交。通知可点开对应任务。调度使用系统不精确闹钟，后台省电可能延迟，强行停止后需要重新打开应用；目前已通过构建及 JVM 规则测试，锁屏、重启和通知点击需真机验证。

1. 把 APK 传到手机安装，打开 **CampusInbox 校园智能任务Agent**。
2. 在收件箱点“登录并同步学习通”。官方页面按手机单栏显示，可切换“扫码登录 / 账号登录”；账号输入、登录处理器和验证仍由学习通原页面负责，本应用不读取输入内容、不自动接受协议。
3. 使用学习通 App 扫码并确认。二维码就在当前手机时，先截图展示到另一块屏幕再扫描，也可切换官方账号登录。二维码失效时点击“刷新二维码”或官方“重新获取”。不承诺学习通支持从同一手机相册识别登录二维码。说明收在右上角；学校验证、未知页面布局或显示异常时可“说明 → 查看官方原版”，也可切回手机布局；切换会重载页面，未提交输入可能丢失。
4. 登录成功后继续打开课程通知，按每批最多 5 条完成一轮检查（最多 100 条），保存后返回收件箱。已登录时可点“同步学习通”，或收件箱、全部消息的“刷新”；首页显示实际检查、保存、新增任务、未读和保存失败数。整轮最多请求一次新增任务提醒。通知栏已划掉的内容若仍保留在课程通知网页，也可由此补收。“我的 → 打开学习通 / 聊天消息 / 课程通知”保留手动浏览和读取；登录门户本身不代表已经读取消息。
5. 在首页点“开启 / 检查手机提醒”，允许 CampusInbox 发送通知，并在 Android 设置中允许它访问通知。学习通实际发布新的系统通知后，原文保存到本机，CampusInbox 也显示一条可点开的提醒；点击直达该消息原文。接收服务断开时会请求重连，打开本应用时也会重试；真正连接后会自动补收通知栏中尚未划掉的学习通通知，并仅为新入库消息提醒。“账号 → 补收当前通知栏”仍为手动静默补收。
6. 进入“任务”核对草稿的名称、课程、截止和原文，确认后再记录进度。“已提交”是你的手动记录，不代表学习通平台回执。

手机包含首页、消息、任务、截止日历、账号五页。日历按截止日期分组、每秒显示当前北京时间；已逾期未提交任务标红并显示“已逾期（未提交）”，已取消任务隐藏。日期未写时刻不会补造 23:59，只有日期的任务从下一天开始视为逾期。

## 读取与存储边界

- 官方网页读取只在该页面打开期间运行：聊天最多读取已加载的最近 100 个会话，每轮轮转 3 个，每个读取已加载的最近 100 条文字；通知最多最近 100 条，每批最多 5 条。首页发起的一轮同步完成后返回收件箱；手动来源页面保持打开时继续轮转读取。不是完整历史导出，网页变化可能需要重试。不翻页补全历史，不代发消息、不代交作业。
- 后台接收依赖 Android 通知访问权限和学习通发布的系统通知；系统可能只提供摘要、截断文字或隐藏内容。只在应用内显示、没有发到系统通知栏的内容不会被后台监听取得。图片、音视频、说明附件请在学习通核对。
- CampusInbox 在新系统通知成功写入手机存档后请求提醒；网页读取新生成任务草稿时也会请求提醒。首页发起的整轮同步最多请求一次，手动来源页面按批次处理；重复读取不产生新草稿、不重复提醒。Android 13 及以上还需允许 `POST_NOTIFICATIONS`，系统和用户仍可关闭或静音该通知频道。截止提醒仍需先确认任务并单独开启。原学习通通知仍由学习通自己显示。
- 聊天和通知分别打开入口读取。空页面不能视为已收完；会话标题与当前选择不一致时不保存，未知消息发布时间不推断“明天”等相对日期。
- 原文和已确认任务保存在应用私有目录，不上传到模型服务。收到的任务先是草稿，需要你确认；规则不是零遗漏自然语言理解。
- 写盘失败保留原存档；通知先存入本地待处理队列，成功落库才移除。单条格式错误不阻塞其他正常通知，首页展示失败与重试按钮；存储设备故障时暂停写入。待处理队列最多 200 条，收件箱最多 10000 条。达到限制或重试队列也无法写入时会报错，请保留通知栏内容与应用数据，不要卸载。
- “退出本机学习通账号”清除本应用 WebView 会话和网页存储，保留已收到的消息、任务、稳定去重命名空间与旧电脑配对；同一消息重新登录后不会因随机登录标识生成重复草稿。当前为个人收件箱，不提供多账号独立档案，也不自动撤销 Android 通知访问权限。

## 可选：继续连接电脑

在“账号 → 更多：连接电脑”使用原伴侣流程。电脑运行 `start-lan.cmd`，手机与电脑连接可互通的网络。从电脑网页“手机连接”复制电脑名称和配对令牌，保存并连接；自动寻找失败时填入网页显示的局域网地址。手机自己的 `127.0.0.1` 不是电脑地址。

原身份、令牌、班级、接收应用和待传队列沿用原存储键，默认接收 `com.chaoxing.mobile`。旧电脑待传队列最多 200 条，仅 HTTP 200/201 后移除；启动伴侣、监听连接、新通知或手动“同步一次”会补传，未实现可靠周期后台补传。电脑不在线不影响新手机收件箱保存消息与识别任务。

校园网隔离设备或屏蔽发现时需手动更新地址。更换电脑使用旧配对界面“修改配对 → 更换电脑”。[旧版通知排查](../docs/verification/mobile-notification-diagnostics.md)、[自动发现验收](../docs/verification/mobile-autodiscovery.md)仍适用于该可选入口。

## 源码构建与验证

需要 JDK 17、Android SDK 35 / Build Tools 35.0.0、Gradle 8.11.1。AGP 8.9.2，无第三方应用运行依赖。本机工具路径在 `../artifacts/android-build/build-environment.json`。

在项目根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-android.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\build-android.ps1 -Architecture arm64
powershell -NoProfile -ExecutionPolicy Bypass -File android\run-tests.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\run-tests.ps1 -Browser
```

依赖缓存齐全后可离线构建，导出 `artifacts/mobile/courseinbox-learning-0.3.20-debug.apk`；首次下载打包的中文 OCR 依赖需加 `-Online`。原始输出为 `android/app/build/outputs/apk/debug/app-debug.apk`。在 Android Studio 中也可构建；Gradle 从 `browser-companion/parser.js` 和 `notices.js` 同步只读解析资源。已知登录、门户、课程列表、聊天及通知页面分别加载手机样式；未知学校验证页保留官方原版。官方页顶部“刷新”重载当前页并重新读取可见消息，本机“刷新手机存档”只读取本地数据。刷新前提醒未提交内容可能丢失；首页发起的同步可直接返回收件箱，手动浏览优先走网页历史。跨域电脑版课程嵌入保留原节点，通过“展开课程页”在当前 WebView 打开官方课程地址，不读取或复制登录凭证。

图片兼容脚本与手机布局独立，在官方 HTTPS 顶层页面将学习通官方域名下默认 HTTP 端口的图片 `src`、`srcset`、`<picture><source>` 候选和行内 CSS 背景改为 HTTPS，保留原节点、路径与参数，并观察后续插入和属性变化。只处理图片，不改写视频或其他资源；特殊端口和含凭证 URL 保持不动；HTTPS 失败不降级 HTTP。WebView 保持 `MIXED_CONTENT_NEVER_ALLOW` 和证书错误取消。外部 CSS 文件和跨域嵌入子文档仍不在支持范围；常用跨域课程页需点“展开课程页”成为顶层页面。手机 VPN、DNS 或校园网络异常仍需实机排查。

本地行为、浏览器模拟、编译及签名检查不能替代真实手机验收。仍需在手机确认覆盖安装配置保留、官方扫码与会话持久化、原生页面布局、通知权限和实际后台通知到达。

构建参数 `-Architecture arm`（默认）保留 32/64 位 ARM 本地库，导出普通文件名；`arm64` 导出 `courseinbox-learning-0.3.20-arm64-debug.apk`；`universal` 保留四种架构并导出 `courseinbox-learning-0.3.20-universal-debug.apk`，供 x86/x86_64 开发环境使用。导出前核对实际架构集合和原签名，不将单架构包冒充全架构包。
